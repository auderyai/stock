# Stock 프로그램 철저 준수 원칙

이 문서는 프로그램·실행 루틴을 작성하거나 수정하기 전에 확인하는 단일 기준이다.
원칙 목록은 `EngineeringPolicy`, 실행 검증은 `EngineeringPrincipleVerifier`가 담당한다.

## 1. 설계와 코드

1. 한 객체는 한 책임만 가진다.
2. 의존 방향은 View → Controller → Service → Repository로 유지하고 View에서 DB·SQL에 접근하지 않는다.
3. 새 코드를 만들기 전에 기존 Policy, Strategy, Presenter, Controller, Service, Repository를 찾아 재사용한다.
4. 규칙은 조건문 복제가 아니라 공통 객체에 한 번만 둔다.
5. 중복·임시방편·우회 분기·사용되지 않는 확장을 제거하여 전체 코드 길이를 최소화한다.
6. 작은 수정으로 원칙을 달성할 수 없으면 책임 경계를 바로잡는 구조 변경을 허용한다.

## 2. 데이터와 보안

1. 사용자 변경, 관련 없는 코드, DB 원본, 완료 데이터와 체크포인트를 보존한다.
2. 비밀값·토큰·자격증명·DB 원본을 출력하거나 Git에 넣지 않는다.
3. 조회는 `read_only=True`가 기본이며 쓰기·삭제는 전용 서비스와 명시적 권한으로만 수행한다.
4. 0건·부분 누락·검증 실패를 성공으로 처리하지 않는다.
5. 반복 실행은 멱등이어야 하며 완료 지점 다음부터 재개하고 완료 범위를 재수집하지 않는다.
6. 삭제는 반영 확인, 정확한 대상 계획, 명시적 확인과 메타데이터 동시 정리를 통과해야 한다.

## 3. GUI 결과표와 정렬

1. 모든 결과표는 `ResultTable → DataFrameModel → TablePresentationPolicy`를 사용한다.
2. 숫자는 숫자로 정렬하고 종목코드는 6자리 문자열로 유지한다.
3. 기본 정렬은 해당 화면의 핵심 점수 내림차순, 동점은 종목코드 오름차순이다.
4. 열은 순위·종목코드·종목명, 종합점수·세부점수, 판정 근거, 최신 DB 자료 순으로 표시한다.
5. 내부 점수·원자료 출처·중복 날짜 등 사용자에게 불필요한 열은 공통 정책에서 숨긴다.

## 4. 차트 연동

1. `NewChartWindowStrategy` 또는 `SynchronizedChartStrategy`를 사용한다.
2. 행 선택만으로 차트를 열지 않고 버튼·더블클릭처럼 사용자가 명시한 동작으로 연다.
3. 선택 종목과 현재 정렬된 전체 결과 목록을 차트에 함께 전달한다.
4. 동기화 모드는 기존 차트 한 개를 갱신하며 동일 기능의 새 차트 흐름을 복제하지 않는다.

## 5. 클라우드 수집

1. 클라우드에는 메뉴 5와 메뉴 7만 존재하며 로컬 메뉴 2의 옵션·분기·자료에 접근하지 않는다.
2. 메뉴 5 전체 완료와 0건 아님을 검증한 뒤에만 메뉴 7을 실행한다.
3. 수집 → DB 저장 → 전체 완료 검증 → 암호화 Drive 저장 → 로컬 반영 순서를 지킨다.
4. 정상 자료와 체크포인트를 먼저 저장하고 실패하면 미완료 위치부터 재개한다.
5. 공급원 오류는 정해진 횟수만 재시도하고 코드 오류만 자동 수정 대상으로 분류한다.

## 6. 분석 결과

1. 저장된 DB의 기준일까지 계산하며 미래 자료를 생성하거나 예측을 확정 사실처럼 표시하지 않는다.
2. 실제값, 기준값, 판정 이유와 한계를 함께 표시한다.
3. 파생 캐시는 다시 생성할 수 있어야 하며 원본 DB로 취급하거나 Git에 저장하지 않는다.
4. 모든 차트 분석·학습은 `ChartAnalysisPolicy`를 먼저 확인한다.
5. RSI는 종가 EMA 14·9, MACD 오실레이터는 종가 EMA 12·26·9,
   Slow Stochastic은 5·3·3 EMA를 사용한다.
6. 이동평균은 EMA 5·10·15·33·56·112·224·448, 볼린저밴드는 종가 EMA 20·2를 사용한다.
7. 거래량과 KOSPI·KOSDAQ 종합지수는 Stock PostgreSQL 자료만 사용한다.
8. 최근 3거래일은 단기 시장 충격 변수로만 사용한다. 20·60·252거래일 수익률,
   변동성 국면·최대낙폭·추세와 종목의 시장 베타·상관·초과성과를 함께 사용하여
   종목 고유 움직임과 KOSPI·KOSDAQ 전체 시장 영향을 구분한다.
9. 종목명·시작일·종료일만 받은 학습자료는 DB 구간을 원본으로 기록하고, 패턴 벡터와
   검증용 차트는 DB에서 재생성한다. 이미지나 임시 원본을 인위적으로 만들지 않는다.

## 7. 변경과 검증

1. 작업 전 `git status`로 사용자 변경과 정확한 범위를 확인한다.
2. 동작 변경에는 정상·경계·회귀 테스트를 둔다.
3. 관련 테스트, 컴파일, 아키텍처·가져오기 경계, 표·차트 정책, `git diff --check`를 통과한다.
4. 실제 DB 검증이 필요하면 읽기 전용으로 수행하고 원본 값을 출력하지 않는다.
5. 요청 범위 파일만 스테이징하고 관련 없는 사용자 변경은 커밋하지 않는다.
