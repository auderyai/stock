# Stock Drive 수동 작업

## 프로그램·실행 루틴 최우선 원칙

1. 책임별 객체로 분리하고 한 객체는 한 역할만 담당한다.
2. 중복·임시방편·우회 분기 없이 코드 길이를 최소화한다.
3. 정상 데이터와 체크포인트를 먼저 보존하고 완료 지점 다음부터 재개한다.
4. 모든 실행은 멱등성을 보장하여 반복해도 중복·손상이 없어야 한다.
5. 수집, DB 저장, 전체 완료 검증, Drive 저장, 로컬 반영 순서를 바꾸지 않는다.
6. 0건·부분 누락·검증 실패를 성공으로 처리하지 않는다.
7. 파일과 메타데이터를 함께 관리하고 중간 실패도 안전하게 재시도할 수 있어야 한다.
8. 요청 범위만 최소 수정하고 사용자 자료·비밀값·관련 없는 작업을 보존한다.
9. 삭제는 반영 검증, 계획 표시, 명시적 확인을 모두 통과한 경우에만 수행한다.
10. 관련 테스트와 정적 검사를 통과한 변경만 반영한다.

## GitHub Actions 실행

1. `auderyai/stock` 저장소의 **Actions** 탭을 연다.
2. 왼쪽에서 **Stock daily DB update to Google Drive**를 선택한다.
3. **Run workflow**를 누른다.
4. `target_date`에 거래일을 `YYYY-MM-DD` 형식으로 입력한다.
5. `stage`는 보통 `menu5`를 선택한다. 메뉴 5 성공 후 메뉴 7이 자동 실행된다.
6. 초록색 완료 표시를 확인한 뒤 Google Drive 상태를 로컬에서 검증한다.

메뉴 7만 재개할 때에만 `stage=menu7`을 선택한다. GitHub Actions에서는 메뉴 2를 실행하지 않는다.

## Google Drive 자료를 로컬 PC에 반영

KRX 작업 메뉴에서는 다음 번호로 Drive 작업을 실행할 수 있다.

- `8`: Google Drive 작업 상태와 체크포인트 확인
- `9`: Google Drive 자료를 로컬 PostgreSQL에 반영하고 멱등성 재검증
- `10`: 로컬 반영과 메뉴 7 완료가 확인된 기준일까지 Drive 자료 정리

메뉴 10은 기준일 선택과 삭제 확인을 모두 거치며, 검증되지 않은 자료는 삭제하지 않는다.

`update_stock_from_google_drive.cmd`를 실행한다. 이 명령은 다음 작업을 연속 수행한다.

1. 암호화 자료의 해시를 검증한다.
2. PostgreSQL에 멱등 반영한다.
3. 한 번 더 실행하여 `already_applied`를 확인한다.

명령줄에서는 다음과 같다.

```powershell
.\.venv_krx_menu\Scripts\python.exe scripts\stock_drive_sync.py update-local
```

결과의 `status`가 `verified`이면 로컬 반영이 완료된 것이다.

## 반영 완료 자료 정리

Google Drive 웹 화면에서 파일을 직접 삭제하지 않는다. 메타데이터가 삭제된 파일을 계속 참조하여 다음 동기화가 실패할 수 있다.

`cleanup_synced_google_drive.cmd`를 실행하고 정리 기준일을 입력한다. 이 명령은 다음 조건을 모두 확인한 자료만 삭제한다.

- 로컬 동기화 완료 날짜 이하
- Google Drive 작업 상태에 포함된 날짜
- 메뉴 7 완료 날짜
- 저장 중이거나 복구 재생 중인 체크포인트가 아님

첫 번째 실행은 삭제 계획만 표시하고, 정확한 확인 문구를 입력한 경우에만 실제 파일과 메타데이터를 함께 정리한다.
